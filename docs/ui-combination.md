# 공지에서 상품 정보까지: UI 조합과 검수

2026-10-09. 뱅크샐러드 공고의 상품 정보 변경·DB 최신화 업무를 위해, 한국어 공지에서 AI가 만든 변경 후보와 근거를 담당자가 확인하고 승인하는 운영실을 만들었습니다. 이번 변경은 그 과정이 쉽게 보이도록 화면을 다시 구성한 개인 데모 작업입니다.

## 선택한 조합

사용자가 공유한 로컬 UI Reference Kit의 20개 설명을 읽고, 03·05·19·18의 실제 참고 이미지도 직접 열어 확인했습니다. 다른 프로젝트에서 선택했던 조합과 도메인은 그대로 가져오지 않았습니다. 금융상품 운영 담당자의 결정은 **‘이 원문의 변경 후보를 현재 상품 정보에 반영해도 되는가?’** 하나로 좁혔습니다.

색만 섞은 조합이 아니라 각 요소의 역할을 나눴습니다. 공간감은 작업 지점의 관계를 설명하는 데, 연결선은 순서를 설명하는 데, 분해는 근거를 읽는 데 사용합니다. 사용자 연구로 최적성을 측정한 결과가 아니라 이번 과업에 맞춘 설계 판단입니다.

## 화면의 읽는 순서

1. 위에서 합성 공지 상황을 선택하고 ‘공지 입력·AI로 읽기’를 누릅니다.
2. 가운데 지도에서 한 공지가 어느 단계에 있는지 봅니다. AI 구역의 빨간 경계가 ‘후보와 원문 근거 생성’까지임을 보여줍니다.
3. ‘변경 근거 펼치기’에서 원문, 실제 Qwen 응답, 서버 코드 검사 결과를 확인합니다. AI 인용을 누르면 원문의 해당 위치가 강조됩니다.
4. 지도 오른쪽의 검토 기준값과 후보를 비교하고 승인 또는 보류합니다. 원문·DB 버전은 서버가 다시 검사합니다.
5. 현재 DB와 고객 화면을 확인합니다. 이미 승인한 과거 건의 변경 전 값과 현재 DB 조회값은 구분합니다.

AI는 문장을 읽고 후보·인용·조건을 생성합니다. 검증은 Node.js 코드, 최종 판단은 담당자, 저장과 현재값 조회는 SQLite·고객 화면의 역할입니다. 지도는 이 실제 상태를 표현하며 임의 건수·가짜 처리 진행률을 만들지 않습니다.

## 적용 범위와 한계

- 새로운 지도와 주변 검토 배치, 근거 세 층, 데이터에 연결된 상태 표현을 적용했습니다.
- 기존 서버의 검증·승인 보호와 가상 시간 비교 모델은 유지했습니다.
- 입력은 합성 공지입니다. 외부 금융사 수집이나 24시간 감시는 구현 범위가 아닙니다.
- n8n·외부 SaaS 연결은 계속 보류합니다.
- 참고 이미지나 다른 제품의 자산은 앱에 복제하지 않았습니다. 지도는 직접 만든 SVG입니다.
- 이 변경의 실제 실행 검수와 캡처는 작업 기록 `work/ui-combination/`에 남깁니다. 기존 영상·PDF는 이전 UI의 기록입니다.

검토·승인·변경·오류 캡처는 [README](../README.md)에 있습니다. 실제 모델 정상과 실패 관찰을 구분했으며 모델 정확도나 회사 성과를 측정한 결과가 아닙니다. 테스트에서 모델 응답을 대체한 항목과 실제 로컬 추론 검수는 별개입니다.

모바일 뷰포트 변경이 실제 문서에 적용되지 않아 모바일 육안 검수는 남았습니다. 최종 로컬 화면에는 초기화 후 실제 모델이 근거를 빠뜨려 보류한 기록이 남아 있습니다. README의 승인 대기·완료 캡처는 초기화 전 실제 실행 증거입니다. UI만을 위한 가짜 분석·승인 결과를 넣지 않았습니다.
