# UI 선택과 검수 범위

2026-10-09 · 현재 공개 UI 기준

뱅크샐러드 공고의 상품 정보 변경·DB 최신화 업무를 위해, AI가 공지를 읽고 담당자가 근거를 검토하는 운영실을 만들었습니다. 이번 화면은 **원문 → AI 후보 → 코드 검증 → 사람 판단 → 현재 DB**를 한눈에 읽도록 구성했습니다. 회사 내부 화면의 재현이 아니라 합성 공지를 사용하는 개인 데모입니다.

## 선택한 화면

상단에는 같은 높이의 다섯 단계 카드를, 아래에는 원문·AI 해석·검증·담당자 판단의 네 칸 작업대를 배치했습니다. 단계 카드를 누르면 상세 검토로 이동합니다.

- **후보와 현재값:** 파란 금리는 AI가 읽은 후보, 초록 금리는 현재 DB 값입니다. 승인 전 두 값을 비교할 수 있습니다.
- **AI 경계:** AI 카드 아래 빨간 “AI는 여기까지”는 후보와 근거 생성 구간을 표시합니다. 코드는 독립 검증을, 사람은 승인·보류 판단을 맡습니다.
- **멈춘 이유:** 검증 실패와 원문 변경은 “반영 보류 / 재분석 필요 / 승인 경로 중지”처럼 문구로 표시합니다. 상태를 색만으로 구분하지 않습니다.
- **근거와 행동:** 인용문·적용일·원문 리비전·DB 버전을 승인 행동 가까이에 둡니다. 모델이 별도 조건을 찾지 못한 경우 “별도 제한 미추출”로 표시합니다.
- **정렬과 경계:** 큰 장식을 줄이고 숫자·라벨을 정렬했습니다. 얇고 연속된 테두리와 키보드 포커스 표시를 사용합니다.

처음 보는 사람이 역할과 근거를 따라가기 쉽다고 판단한 설계입니다. 사용자 실험으로 이해 시간이나 업무 효율 개선을 측정한 결과는 없습니다.

## 화면을 직접 확인한 참고 자료

아래 네 자료의 실제 화면을 확인해 배치 원칙을 참고했습니다. 다른 제품의 화면을 자산으로 복제하거나 회사가 이 제품을 사용한다고 주장하지 않습니다. 오래된 자료에는 기준 연도를 함께 적었습니다.

| 자료 | 확인한 화면 | 적용한 부분 |
|---|---|---|
| [Linear sidebar·split view 변경, 2022](https://linear.app/changelog/2022-01-20-linear-preview-new-sidebar-and-team-icons) | 공식 본문과 실제 화면 이미지 | 차분한 탐색 영역과 낮은 대비의 경계 |
| [Tremor](https://www.tremor.so/) | 웹의 표와 선택 상태 화면 | 숫자·라벨 정렬, 얇은 구분선, 선택 상태 색 |
| [Langfuse Annotation Queues](https://langfuse.com/docs/evaluation/evaluation-methods/annotation-queues) | 공식 설명과 확대 화면 이미지 | 입력·출력·검토 행동을 가까이 배치, 모델 출력과 검토 결과 분리 |
| [Eyk 대시보드 게시물, 2022](https://x.com/webeyk/status/1598033326396346402) | 개발자가 게시한 대시보드 사진 | 필터와 결과 구역 분리, 일관된 정보 정렬 |

UI 자료는 디자인 참고이며 회사 수요의 근거와 구분합니다. 직무 연결은 [공식 공고](https://banksalad.career.greetinghr.com/ko/o/91296)와 [회사 근거 기록](../COMPANY-ALIGNMENT.md)의 확인 범위를 따릅니다.

## AI·코드·사람의 역할

| 역할 | 실제 실행 범위 |
|---|---|
| Qwen 로컬 LLM | 한국어 합성 공지에서 변경 후보·인용문·적용 조건·질문 생성 |
| Node.js 검증 코드 | 원문 근거·타입·수치·날짜·고객 범위 검사, 원문/DB 버전 대조 |
| 담당자 | 검증된 후보의 승인·보류와 예외 판단 |
| SQLite·고객 화면 | 승인 결과와 이력 저장, 현재 상품 DB 조회 |

모델 응답만으로 DB를 변경하지 않습니다. 원문 수정 시 이전 해석을 폐기하고, 승인 직전에도 원문 해시·리비전·DB 버전을 확인합니다. 입력은 합성 공지이며 외부 금융사 크롤링·실제 고객 정보·n8n·외부 SaaS 전송은 현재 기본 데모 범위에 포함하지 않습니다.

## 확인한 실행과 남은 검수

| 확인한 조작 | 관찰 결과 |
|---|---|
| 실제 모델의 원문 인용 불일치 | 근거 검사 실패, 반영 보류 |
| 새 공지에서 3.76% 후보 추출 | 7개 검사 통과, 사람 판단 대기, DB 4.50% v1 유지 |
| 담당자 승인 | 같은 DB와 고객 화면이 3.76% v2로 변경 |
| 원문을 3.82%로 수정 | r2, 이전 AI 해석 폐기, 재분석 필요 |
| 이전 검토로 승인 시도 | 승인 거부, DB 3.76% v2 유지 |
| 모델 응답 실패 | 명시적 오류, 샘플 응답 생성 없음, 기존 DB 유지 |
| 초기화 | 접수 0건, 상품 DB 4.50% v1 복구 |
| 새로고침·키보드 Tab | 기록 재조회와 초점 이동·포커스 테두리 확인 |

**핵심 로직 테스트 56개 통과·실패 0개**를 확인했습니다. 이는 전체 UI 자동 검증이나 실제 모델 정확도 벤치마크가 아닙니다. 화면 모듈은 별도의 상태·이스케이프·콜백 검사와 실제 브라우저 조작으로 확인했습니다. 세부 실행 기록은 [VERIFICATION.md](../VERIFICATION.md)를 참조하세요.

1280px 데스크톱에서 문서 폭과 핵심 조작을 확인했습니다. 브라우저의 모바일 크기 변경을 두 차례 적용했지만 실제 문서 뷰포트가 1280×720에 머물러 임시 설정을 해제했습니다. 반응형 CSS는 포함되어 있으나 **개선 UI의 모바일 육안 검수는 아직 완료되지 않았습니다.**

현재 화면은 [README의 실제 캡처](../README.md#현재-ui--ai가-맡는-구간부터-승인-결과까지)와 [최신 3페이지 포트폴리오](portfolio/financial-product-ops-portfolio.pdf)에서 볼 수 있습니다. YouTube의 [112초 영상](https://youtu.be/XPwjsHmasuI)은 개선 전 UI의 정지 화면을 편집한 초기 시연입니다.
